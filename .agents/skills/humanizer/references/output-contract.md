# Writing contract

Every paragraph must answer the reader's question, add evidence or necessary reasoning, or make the next action clear. Remove a sentence whose only job is to announce importance, praise a plan, or repeat a conclusion. Preserve material uncertainty, failures, limitations, and source links.

Use connected plain paragraphs for conversation. Avoid decorative headings, bold labels, emoji, horizontal rules, and a stack of one-sentence fragments. Lists belong to actual sequences or parallel items; tables belong to useful comparisons. A document may use descriptive headings to aid navigation. Keep required artifact formats and explicit user preferences. Markdown itself is not a defect; decoration and empty structure are.

Start with the answer rather than canned enthusiasm or a restatement of the request. Prefer concrete verbs and supported claims. Remove stock phrases such as `great question`, `let's dive in`, `it's worth noting`, and `bottom line`. Do not end with a recap that repeats the same answer or an offer to do work already requested.

Replace empty adjectives with the property and evidence they were meant to convey. A change may have passed specified tests; that does not establish that it is “production-ready.” A “robust standard error” is a technical term and should remain when accurate. A contrast is useful when both sides explain a real distinction; do not invent an inferior alternative to dramatize the chosen approach.

Preserve the writer's facts and voice. Do not invent an anecdote, feeling, quotation, source, measurement, or personal experience. Check numbers, units, comparisons, scope, links, and qualifications against the input. Source quotations and code must remain exact. Keep an honest statement that a check did not run.

For an experiment update, state the result and decision in ordinary prose. For example: “The candidate reduced median latency from 420 ms to 310 ms across five matched runs. Correctness checks passed. Field validation is pending.” Only use those numbers when they are the actual measured result. A template example is never evidence.

Use the writing checker as a final mechanical screen for saved prose. Plain mode flags decorative headings, bold labels, horizontal rules, and emoji as well as a small set of canned phrases and exact repeated paragraphs. Document mode allows headings and structural dividers. It skips code, YAML frontmatter, block quotations, and link destinations to avoid rewriting technical content or attributed examples. A finding requires inspection; a clean result still requires a review of meaning. No script can guarantee good prose or detect all empty language.

Keep the explanation as long as the task warrants. There is no universal word or token cap, no quota of banned words, and no need to narrate the editing process to the reader.
